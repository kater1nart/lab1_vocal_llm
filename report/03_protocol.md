## 3. Единый протокол сравнения

| Элемент протокола | Значение (одинаково для всех моделей) |
|---|---|
| Тестовый набор | `cmp_test`: 200 клипов, по 50 на класс, артисты не пересекаются с train/val |
| Вход | PNG лог-мел спектрограммы первых 10 с (448×224, 128 мел-полос, 0–8 кГц, подписи частот) |
| Инструкция | Одна и та же англоязычная инструкция: определения четырёх классов, описание осей спектрограммы, подсказка о диапазоне основного тона мужского и женского голоса (`src/run_llm.py`, `TASK` + `INPUT_DESC`) |
| Формат ответа | Строго JSON `{"label": "<male\|female\|group\|instrumental>", "confidence": <0..1>}` |
| Zero-shot | Одна целевая спектрограмма |
| Few-shot | 4 размеченные эталонные спектрограммы (по одной на класс, фиксированные clip_id из train, фиксированный порядок male → female → group → instrumental) + целевая, в одном сообщении |
| Генерация | temperature = 0 (greedy), max_tokens = 48 (у Gemini 64, thinking отключён) |
| Порядок объектов | Фиксированная перестановка (`random_state=0`), классы перемешаны |
| Невалидный ответ | Нет JSON, JSON не парсится или метка вне списка классов. Такой ответ считается ошибкой в метриках качества и учитывается отдельно как `invalid_rate` |
| Железо | Apple M3 Pro, 36 ГБ, MLX (4-bit квантизация) |

**Модели сравнения:**

| Модель | Тип | Параметры | Доступ | Почему выбрана |
|---|---|---|---|---|
| Qwen2.5-VL-7B-Instruct (MLX 4-bit) | open VLM | 7B | локально | сильная открытая VLM с поддержкой нескольких изображений в запросе |
| Gemma-3-4B-it (MLX 4-bit) | open VLM | 4B | локально | компактная VLM другого семейства — проверка, зависит ли результат от модели |
| Gemini 2.5 Flash | проприетарная VLM | — | API (бесплатный tier) | API-модель; работа Dixit et al. показала, что проприетарные VLM лучше справляются с задачей VSC |
| LogReg на мел/MFCC | обучаемый baseline | ~1 тыс. весов | локально | нижняя граница «дёшево и обучено»: проверка H3 |

**Метрики** (направление улучшения задано заранее): Macro-F1 (основная, ↑) с 95% bootstrap-интервалом (1000 выборок); F1 по классам (↑); MCC (↑); balanced accuracy (↑); доля невалидных ответов (↓); ECE по заявленной уверенности, 10 бинов (↓); латентность p50/p95 (↓); стоимость API на 1000 клипов (↓).

**Правило выбора лучшей LLM (зафиксировано до запуска):**
1. Исключаются модели с долей невалидных ответов ≥ 5% или Macro-F1 ≤ 0,40 (порог H1: случайный уровень 0,25 + 0,15).
2. Среди оставшихся выбирается модель с максимальным Macro-F1 в лучшем режиме (zero- или few-shot).
3. Если 95% интервалы лидеров перекрываются, выбирается более дешёвая модель (сначала стоимость, затем p95 латентности).
4. Если ни одна LLM не проходит фильтр, «лучшей» считается LLM с максимальным Macro-F1. Она применяется к срезу большего объёма для анализа ошибок, а вывод о целесообразности формулируется отрицательно.
